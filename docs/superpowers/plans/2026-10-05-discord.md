# Discord member delivery implementation plan

**Goal:** Connect curated public-source daily items to the user's eight existing Discord channels, including a complete daily summary.
**Architecture:** ADR-0010; domain edition contract → application curation → renderer → webhook Publisher with durable checkpoint journal → composition. Existing pipeline remains the source of automatic input.
**Tech Stack:** TypeScript, existing LlmProvider/HttpClient/CheckpointStore/Publisher, native fetch, Discord webhooks.
**Spec:** docs/adr/0010-discord-member-digest.md

## Global constraints

No commit/push. No private notes or server conversations in content. No secret logging. General-audience Korean; label examples 활용 예시. 00 includes all successfully published daily items. Config disabled until live verification. Work in this user-selected workspace; tasks own disjoint files. Source expansion is reported separately, never falsely claimed complete.

## Task 2: Webhook transport and durable delivery

- [x] `DiscordPublisher implements Publisher`, constructor `{guildId,routes:Record<DiscordChannelKey,{webhookUrl:string,channelId:string}>,checkpoints:CheckpointStore,clock:Clock,http:HttpClient,logger?:Logger,sleep?:(ms:number)=>Promise<void>}`. Consumes DiscordDeliveryPayload; validates destinations once per publish.
- [x] Durable checkpoint by guild/date. Store intent before POST and confirmed IDs after, retain previously delivered posts. Mark ambiguous creations and block resend. Definite rate-limit response may retry bounded times. PATCH known IDs; never delete. Journal per summary page as well.
- [x] Publish details, build 00 grouped summaries from union of successful daily posts, chunk to <=2000 and link every post. Keep successes and retry definite failures. Expose failures without losing progress. `externalUrl` first summary page; `externalId` journal identity.
- [x] Extend HttpRequest method with PATCH as needed. Never include URLs/tokens/raw response bodies in errors. Dry run makes zero HTTP calls/checkpoint writes and logs preview only.
- [x] Fake HTTP/checkpoint tests for partial resume, summaries, mentions, lengths, ambiguous responses, changed revisions, 429, destination mismatch, dry-run.
